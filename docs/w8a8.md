# W8A8 fragment 卷积

`DiffusionLab/W8A8` 是 Unity 2022.3、D3D11 Shader Model 5 的 fragment shader。激活和权重都按每个 RGBA8 UNorm texel 四个有符号 INT8 lane 打包；量化范围为 `[-127,127]`，字节编码为 `q+128`，所以量化零是字节 `128`。Shader 用 `floor(value*255+0.5)-128` 解码，屏蔽输入和输出通道尾部，并以编码零作为卷积 padding。支持 1×1 linear 与 3×3 卷积、stride、padding、逐输出通道权重 scale、bias、ReLU、浮点反量化和输出重数量化。量化舍入采用最近整数、half ties away from zero，输出饱和到 `[-127,127]`。

INT32 累加由手写 `int4` 乘积与加法完成；这是 SM5 标量/向量整数乘加，不代表硬件 DP4A 指令。任意输入下要求 `K=Cin×Kernel×Kernel≤133144`，其中每项的绝对值最大为 `127×127=16129`；偏置在反量化后以浮点数加入。Pass 0 输出精确 INT32 到 RGBA32_SInt（ARGBInt）目标。PlayMode 的 VRC 异步读回路径使用 Pass 9 将每个 int32 的 two’s-complement 位模式按小端拆成 RGBA8，再读回字节并在 CPU 端重组；它没有经过浮点转换。

| Pass | 用途 |
| --- | --- |
| 0 | INT32 累加器 |
| 1–2 | W8A8 浮点输出、输出重数量化 |
| 3–4 | FP32 参考、W8Afloat 参考 |
| 5 | 激活量化打包 |
| 6–7 | 累加器反量化、重数量化 |
| 8 | RGBA8 UNorm 全字节往返检查 |
| 9 | INT32 位模式到 RGBA8 的精确读回编码 |

数值验证包含十个形状/累加用例、正负 INT32 安全上界、首个不安全归约长度拒绝、正负重数量化 tie 与饱和、激活量化 tie，以及全部 256 个字节码往返。PlayMode 使用真实 UdonSharp runner、`VRCGraphics.Blit` 和 `VRCAsyncGPUReadback` 的 `TryGetData(byte[])` 验证卷积、重数量化和第二层 INT32 读回；记录的浮点最大绝对误差为 0。浮点参考采用相同的量化后数值；这证明算子计算正确，不代表原模型量化后的画质无损。本轮没有接入或评价量化 SD 模型。

基准在 RTX 5080 / Direct3D11 上运行，比较相同逻辑 shape、GPU 常驻输入和 RGBA32F 输出；每条路径 1 次预热、5 次测量。表中是 **dispatch + GPU 完成等待 + 读回** 的墙钟中位数，括号内为相对 FP32 的时间比，低于 1 表示用时较少。基准排除了激活打包、归一化和完整模型流程。

| 路径 | MNIST 28×28 C128 3×3 | SD channel 16×16 C320 3×3 | 64-token C320 1×1 |
| --- | ---: | ---: | ---: |
| FP32 storage / FP32 math | 0.960 ms (1.000×) | 1.553 ms (1.000×) | 0.625 ms (1.000×) |
| FP16 storage / FP32 math | 1.105 ms (1.151×) | 1.612 ms (1.038×) | 0.540 ms (0.863×) |
| W8A16 storage / FP32 math | 1.026 ms (1.069×) | 1.982 ms (1.276×) | 0.609 ms (0.974×) |
| W8A8 storage / INT32 math | 1.034 ms (1.077×) | 1.846 ms (1.189×) | 0.477 ms (0.763×) |

计时诊断在临时开启 Profiler 和 GPU area 后仍报告 `gpuRecorderSupported=true`，但 12 项 marker 的 `gpuMilliseconds` 仍为空、`gpuMedianMs` 仍为 null。因此没有可报告的纯 GPU 时间或 GPU 时间比值；上表使用最终关闭 Profiler 的独立测量，只能解读为包含读回的墙钟结果。前两次诊断保留在 [初次记录](../results/w8a8-benchmark-initial.json)与 [Profiler记录](../results/w8a8-benchmark-profiled.json)，多次观测有波动，不能据此承诺完整 SD 模型的加速。

结果文件：数值验证 [w8a8-numeric.json](../results/w8a8-numeric.json)、PlayMode [w8a8-playmode.json](../results/w8a8-playmode.json)、基准 [w8a8-benchmark.json](../results/w8a8-benchmark.json)、D3D11 字节码检查 [w8a8-bytecode.json](../results/w8a8-bytecode.json)。

在工程目录运行数值验证、检查 shader 状态和导出 D3D11 pass 0 字节码：

```sh
python tools/unity_remote.py run_script --file AgentScripts/ValidateW8A8.cs --entry ValidateW8A8.ShaderStatus
python tools/unity_remote.py run_script --file AgentScripts/ValidateW8A8.cs --entry ValidateW8A8.Numeric
python tools/unity_remote.py run_script --file AgentScripts/InspectW8A8Bytecode.cs --entry InspectW8A8Bytecode.Export
```

PlayMode 按顺序调用 `BuildPlayFixture`、`CompilePlayFixture`，等待 Udon 编译结束后调用 `FinishPlayFixture` 和 `OpenPlayScene`；然后进入 Editor PlayMode，调用 `Play`，停止 PlayMode，再调用 `ClosePlayScene`。基准在 EditMode 调用 `StartBenchmark`；需要尝试 GPU Profiler 采集时单独调用 `StartProfiledBenchmark`（会恢复原设置）。随后轮询 `BenchmarkStatus`，直到状态变为 `completed` 或 `failed`。

测试会经过 SDK/ClientSim 的项目检查；复测前应记录音频 voice budget 与主世界 sampler 的纹理绑定，结束后用 Editor API 恢复。`RestoreValidationSideEffects` 接受捕获的 virtual/real voice 数和两个纹理 GUID，不能直接套用其他人的设置。本轮已恢复这些临时变化，并逐个 SHA 核对原有49个未提交文件保持原样。
